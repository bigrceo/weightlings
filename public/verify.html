What this proves, and what it does not

It proves

  • The arithmetic. Given the frozen snapshot and the seed, the ranking, the 35% cut, the second chances, the parents and the mutations are exactly what the published function returns. Your browser just ran it. The function is one readable file per version of the rules: cull.v2.js. From version 2 on, the file's hash is inside the commitment, and this page hashes the bytes it downloads before running them.
  • The seed. It is the hash of the stated Robinhood Chain block. Your browser read that block from the public RPC, not from us, and checked that it is the first block at or after the trial second. From rules version 2 on, that second is inside the hashed commitment, so one commitment hash allows one block only. In version 1 rounds it is stored beside the hash, not inside it.
  • The counts we print. Entered, died, born, mutations, each brain's tally and the dominant brain on the round card are recounted here from the recomputed result.

Outside timestamp

It does not prove

  • When the snapshot was fixed. The commitment is published by our own server at /api/commit, one minute before the seed block, and kept in a log at /api/commits where each entry names the one before it. Both are ours. Nothing is anchored on Robinhood Chain. From round 44 on, each commitment and each result hash is also sent to the public OpenTimestamps calendars, which anchor it in Bitcoin within hours; where a proof file is listed on this page, it fixes that hash in time independently of us. Without one, the timing rests on our clock, and whoever runs the server could rewrite the record and the log together. A copy kept outside our server shows it: if this page is open during the sealed minute it keeps one and compares it afterwards.
  • The hour before. The foraging that fills the snapshot (who ate, won, shared, fainted) runs on our server and cannot be recomputed. Those counts weigh more in the score than the dice do. A server restart can cost part of the hour; the commitment says how much.
  • Which lineages wait. The list of extinct lineages in a snapshot is drawn up by our server. When it is long, only a part enters the draw: holders first, then the longest gone.
  • Intelligence. Traits are simulated from the numbers on each model card. No AI model is run.
How a round is drawn
  1. One minute before the trial the meadow is frozen: every living creature with its hour of foraging, the extinct lineages, the brain table, the trial second, the id of the first newborn, the hash of the rules file and the hashes of the round before. The SHA-256 of that input is published.
  2. The dice are the hash of the first Robinhood Chain block whose timestamp is at or after the trial second. That block does not exist yet when the snapshot is hashed, as long as the hash was published when our server says it was. See what this page does not prove.
  3. The cull scores every creature (trial weights on its traits, its hour of foraging, crowding by model, tier and lineage, and noise from the dice), removes the weakest 35%, gives up to a quarter of the free places to extinct lineages, and breeds the rest from the survivors with a 12% chance of mutation.
  4. The record keeps the input, the block, the result and the version of the rules, so the same function gives the same answer for anyone, at any time.
  5. If the result cannot be written, the same commitment waits for the same block and is tried again. A round that still cannot be written is voided in the open: its commitment and seed block stay in the log, nobody dies, and its number is not used again.
